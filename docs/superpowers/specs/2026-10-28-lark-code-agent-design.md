# 飞书群「蔡龙」代码问题自动分析服务 — 设计文档

日期：2026-10-28
状态：已确认设计，待写实现计划

## 1. 背景与目标

策划群里运营经常提出线上问题（例如"玩家领取竞技场排名奖励没到账，查一下代码"）。目前靠人工翻代码定位，响应慢。

目标：在群 `武器店策划程序沟通` 中，出现触发词后由本地常驻服务拉取最新项目代码，用 AI 分析问题根因，并把结论以"回复该消息"的形式发回群里。

成功标准：

- 运营在群里发「蔡龙 + 问题描述」，30 秒内收到确认提示
- 任意群成员回复「确认」后，服务自动同步代码并开始分析
- 分析结果以回复原消息的形式出现，包含结论、文件路径与行号、依据、建议

## 2. 不做什么（v1 范围外）

- 卡片按钮确认（需要机器人进群 + 事件订阅，见 §5）
- 群消息中的图片 OCR / 截图解析（只处理文本）
- 多群、多任务并发分析
- 以机器人身份发言（v1 全部以用户本人身份发出）
- 自动把机器人拉进群、自动申请敏感权限

## 3. 关键约束（实测结论）

| 约束 | 实测结果 | 影响 |
|---|---|---|
| 机器人身份发言 | `230002 Bot/User can NOT be out of the chat`，蔡龙不在群内 | v1 只能用用户身份发言 |
| 机器人私聊 | `230013 Bot has NO availability to this user` | 机器人身份不可用于 DM |
| 读群消息 | `+chat-messages-list` 需要 `im:message.reactions:read`，当前用户授权未包含 | 必须先补授权 |
| 卡片回调 | `card.action.trigger` 仅应用身份可收 | v1 用文字确认 |
| 代码仓库 | `/d/Project/Idle_Outpost` 有未提交改动 | 必须用独立副本，禁止操作原工作区 |

## 4. 架构

单进程 Node.js 服务（Node 24，仅用内置模块，通过 `child_process` 调用本机 `lark-cli` 与 `codex`）。

```
群消息 ──poll(15s)──> 触发判定 ──> 状态机 ──> 仓库同步 ──> codex exec ──> 回复原消息
                         │
                         └── 等待确认(600s) ──> 确认/取消/超时
```

### 4.1 组件

| 模块 | 职责 | 依赖 |
|---|---|---|
| `src/lark.js` | 封装 lark-cli：拉取群消息、回复消息、发送消息；统一解析 JSON 信封（`ok` 字段），错误分类 | `lark-cli` |
| `src/trigger.js` | 纯函数：触发词判定、确认词判定、消息去重 | 无 |
| `src/state.js` | 状态机：空闲 / 等待确认 / 分析中；持久化游标与进行中任务 | 文件系统 |
| `src/repo.js` | 克隆与同步专用副本，返回 commit sha | `git` |
| `src/analyze.js` | 构造提示词、调用 `codex exec`、清洗输出、超时控制 | `codex` |
| `src/reply.js` | 组织回复文本，长度裁剪，附 commit 信息 | 无 |
| `src/index.js` | 主循环：轮询、推进状态机、串行调度 | 以上全部 |

### 4.2 目录

```
E:\lark-code-agent\
  config.json            配置
  state\state.json       游标 + 进行中任务
  logs\app-YYYY-MM-DD.log
  logs\jobs\<message_id>.md   单次分析原文
  repo\Idle_Outpost\     专用代码副本（独立 clone）
  src\*.js
  test\*.test.js
```

## 5. 身份与权限（v1）

- 所有飞书调用使用 `--as user`，即蔡逸鹏本人账号。群里看到的发言人是他本人。
- 服务启动前必须完成一次增量授权：`im:message.reactions:read`。
- 机器人「蔡龙」在 v1 只作为服务名与触发词存在，不参与发言。

## 6. 触发与确认规则

### 6.1 触发

满足全部条件才算一次触发：

1. 消息属于 `chat_id = oc_dd37d502d8e49d7e2f5f993a4841b819`
2. 发送者不是本账号（避免自触发死循环）
3. `create_time` 晚于服务启动时间（不回溯历史消息）
4. 消息类型为 `text` 或 `post`，抽取纯文本后包含「蔡龙」
5. 该 `message_id` 未被处理过

命中后：回复原消息「收到。请任意群成员在 10 分钟内回复「确认」开始查询，回复「取消」放弃。」并进入等待确认状态。

### 6.2 确认

- 窗口：提示发出后 600 秒
- 取消：整条消息（去空白后）等于「取消 / 取消查询 / 忽略 / 不用」
- 确认：整条消息（去空白后）等于「确认 / 确认查询 / 同意 / 开始查询 / 开始 / 1」
- 判定要求整条短消息匹配，避免正常聊天里出现"确认"两个字被误判
- 确认可以由本账号发出（方便自己确认）；服务发出的提示长度超过匹配规则，不会自我触发
- 确认人昵称记录并在结果中回显
- 超时：回复「查询请求已超时，如需分析请重新发起」

### 6.3 互斥

同一时刻只允许一个任务：

- 等待确认时又来新触发 → 回复「已有查询待确认，请先确认或取消」
- 分析中又来新触发 → 回复「正在分析上一个问题，请稍后」

## 7. 仓库同步

- 首次：`git clone --branch master <repo_url> repo/Idle_Outpost`
- 每次：`git fetch --prune origin` → `git reset --hard origin/master` → `git clean -fd`
- 记录 `git rev-parse --short HEAD`，随结果一起发出
- 同步失败：回复「拉取代码失败：<简短原因>」，任务终止，不回退到旧代码分析

仓库：`https://codeup.aliyun.com/5f2b9f02df9df74e36afc9ad/Idle_Outpost.git`，分支 `master`。
严禁触碰 `/d/Project/Idle_Outpost`。

## 8. 分析引擎

### 8.1 调用方式

`codex exec`，工作目录固定为专用副本，只读沙箱，提示词通过 stdin 传入，超时 600 秒。
具体沙箱与非交互参数以本机 `codex exec --help` 为准，实现时先验证再固化到配置。

### 8.2 提示词契约

输入给 codex 的内容包含三块，用明确分隔符隔开：

- 只读约束说明：不得修改仓库任何文件，只做检索与阅读
- 运营问题原文 + 该消息之前 5 条群消息（作为上下文）
- 要求的输出结构

要求输出：

```
【结论】一句话说明问题性质（代码缺陷 / 配置缺失 / 数据问题 / 无法判定）
【定位】文件路径:行号，最多 3 条
【依据】关键代码或逻辑链，2-4 句
【建议】给程序的修复方向，1-2 句
```

若定位不到，必须明说「代码中未找到直接相关逻辑」，并列出已检索的关键词与模块，禁止编造行号。

### 8.3 安全

- 群消息文本视为不可信输入，只作为数据拼接，禁止参与命令行构造
- 仓库只读，防止通过聊天内容诱导改代码
- 输出清洗：去除 ANSI 转义，长度上限 4000 字符

## 9. 回复格式

以回复原消息的形式发出：

```
【结论】…
【定位】Assets/Scripts_xxx/A.cs:123
【依据】…
【建议】…
—— 蔡龙自动分析 · master@a1b2c3d · 由 <确认人> 确认
```

超长时截断正文，完整版写入 `logs/jobs/<message_id>.md` 并在末尾注明路径。

## 10. 配置项（config.json）

| 键 | 默认值 | 说明 |
|---|---|---|
| `chatId` | `oc_dd37d5…` | 监听的群 |
| `triggerKeyword` | `蔡龙` | 触发词 |
| `confirmTimeoutSec` | `600` | 确认窗口 |
| `pollIntervalSec` | `15` | 轮询间隔 |
| `contextMessages` | `5` | 上下文条数 |
| `repo.url` / `repo.dir` / `repo.branch` | 见 §7 | 仓库 |
| `analyze.timeoutSec` | `600` | 分析超时 |
| `dryRun` | `false` | 只打日志不真发消息 |

## 11. 失败处理

| 场景 | 行为 |
|---|---|
| lark-cli 调用失败 | 记录日志，本轮跳过，下轮重试；连续 5 次失败则在日志告警 |
| 授权失效（token 过期） | 日志提示需重新 `auth login`，停止轮询，不重复报错刷屏 |
| git 同步失败 | 回复失败原因，任务终止 |
| codex 超时 / 非零退出 | 回复「分析失败/超时」，保留原始输出到 `logs/jobs/` |
| 进程崩溃 | 状态文件保留进行中任务；重启后按超时规则作废，不自动重跑 |

## 12. 运维

- Windows 计划任务，登录时自启，无窗口运行
- 日志按天切分，保留 14 天
- 提供 `--once`（单轮）与 `--dry-run`（不发送）用于手工验证

## 13. 测试计划

- 单元测试（`node --test`）：触发词判定、确认词判定、去重、状态迁移、文本裁剪
- 集成测试（dry-run）：给定伪造消息序列，断言发出的回复内容与顺序
- 手工端到端：群里发「蔡龙 测试一下」→ 回复确认 → 收到分析结果
- 异常路径：仓库不可达、codex 超时、确认超时

## 14. 上线前置条件

1. 补授权 `im:message.reactions:read`
2. 验证用户身份可读该群消息（`+chat-messages-list` 返回正常）
3. 首次 clone 专用副本
4. 用户单独确认后安装计划任务
