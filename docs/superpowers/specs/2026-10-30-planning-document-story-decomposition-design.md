# 蔡龙：策划文档拆分与 TAPD 父子需求

日期：2026-10-30
状态：聊天方案已确认；书面规格待用户审阅，尚未进入实施。

## 1. 目标与边界

策划显式发送文档后，蔡龙自动阅读、生成可审核的功能拆分；审核人确认内容和目标项目后，创建或关联一个 TAPD 总需求，并在其下创建功能子需求。

首版包含：显式触发、内容提取与覆盖检查、自然语言修改草稿、分页审核、父子需求创建、重复识别、部分失败恢复。自动分析不等于自动建单。

不包含：监听任意文档编辑、自动覆盖既有需求、删除需求、自动派工或估工期、自动修改游戏代码、默认扫描游戏仓库、自动发布生产服务。文档增量同步和任意链接递归抓取不在首版范围。

首版流程只在明确配置的自测入口启用。不得修改生产配置、重启生产实例或向业务群发送测试消息。真实 TAPD 写入验证须另获用户授权，不因本规格获批而自动获得授权。

## 3. 用户交互

### 3.1 触发与路由

约定消息：@蔡龙 拆分需求 <飞书文档链接>。文本和富文本均可；普通转发链接不触发。以显式需求命令优先于既有故障关键词判定，避免进入代码排查流程。

一个请求只处理一个主文档。多个主文档链接时提示选择，不悄悄选第一份。主文档链接支持已核实的 docx；wiki 链接解析为文档后使用同一流程，非文档节点明确提示不支持。

只有配置允许的群和发起人可触发。审核者默认为发起人，额外审核者须按项目配置明确授权；不能把“能点击群卡片”等同于“能批准建单”。每次修改与提交均检查身份、群、消息、请求和版本。

项目能可靠识别时仅预选，不能确定则要求选择。TAPD workspace、凭据和允许人员来自服务端配置，文档和模型不能指定任意目标。目标项目须在提交前明确确认。

### 3.2 草稿审核

初始卡显示正在读取/分析；完成后显示文档版本、项目、子单数量、阻塞问题和素材覆盖情况。提供分页清单、单张详情、返回、取消以及确认提交操作。

草稿支持“回复审核卡片所在消息线程并明确修改请求”的自然语言调整。没有唯一请求上下文时，要求携带请求标识；不把普通群聊当作编辑。示例：将奖励和红点拆开、排除本期头像框、修改某子单负责人。

每次有效修改递增草稿版本，重新校验覆盖、来源和依赖。切换展示页只改变视图，不改变已审核内容；所有能修改内容或产生写入的旧版本按钮均失效。再生成不得无声丢弃审核人已经确认的修改。

确认页必须展示：新建还是关联已有父单、目标项目、父子类型、父单与子单迭代、负责人、待创建清单、排除/暂缓清单，以及总写入数量。不能用一个未展示子单内容的摘要代替审核。

不要求所有问题解决后才能提交；审核人可选择无阻塞且依赖完整的子集。受阻塞影响及依赖未满足的子单暂缓，并明确列在确认页。后来批准的剩余子单继续关联原父单，不重建父单。

卡片负载必须遵守现有 30 KiB 限制。分页和单条详情分段不得截掉业务规则而不提示；完整草稿以本地持久化记录为准，不依赖卡片展示文本重建。

## 4. 文档读取与证据

文档提取保留：规范化文档 ID、标题、来源链接、版本、标题层级、块标识、正文、表格、可见评论及资源清单。

- 正文和普通表格：完整读取，保留条目结构。
- 图片/画板：受控下载或预览并进行视觉识别；图片 alt 只作辅助线索，不视为看过原图。
- Excel/内嵌表：通过对应读取能力获取有意义的单元格内容，记录读取范围。
- 视频：首版记录资源和关联功能，不承诺自动解析完整时序；由审核人提供确认的演出说明，或暂缓依赖该视频的子单。
- 外链参考：保留出处，不默认无限追踪。需要纳入时显式扩展本次来源清单。
- 评论：保留来源和语境；无法证明完整读取时标明仅包含当前可见评论，不承诺全文评论无遗漏。

资源清单中每一项都必须是已解析、已由审核人提供说明、明确排除或待处理，禁止静默丢弃。读取失败、无权限、不支持或达到处理上限时记录原因，阻塞受影响的子单。授权审核人可明确声明某素材仅作非功能参考并排除，留下理由；不能把“未读”标成“已读”。

来源快照包括主文档版本和实际读取内容指纹；关联素材有独立版本时记录版本，否则记录内容指纹。主文档版本不能代表附件一定未变。提交前重检参与该批次的来源；读取失败或变化则暂停，提示重读和重新审核。

## 5. 拆分契约

### 5.1 粒度

一张子需求对应一个边界明确、可开发、可验收的功能闭环，而不是一个章节、一个按钮或一个配置实例。

- 同一功能散落在 UI、功能说明和表格中的规则合并。
- 同一功能的未开启、进行中、可领取、已领取等状态放在同张子单中。
- 活动周期、公共进度、奖励等交付边界不同的能力可分别拆分。
- 相同算法、不同配置不逐实例重复建单；接口、行为或交付边界不同才进一步拆分。
- 共用规则只有一个归属，其余子单以依赖引用，避免重复承诺。
- 不固定子单数。大模块必须能说明自己的输入、行为、结果和验收边界。

### 5.2 内容可信度与覆盖

提取原子要求后，为每项分配稳定标识和来源。每项必须映射到至少一张子单、一个待确认项或一个明确排除项。跨模块要求有主归属，可有引用。

每张子单包含：稳定标识、标题、功能规则、验收条件、依赖、来源引用、待确认项、审核状态和人员字段。依赖使用稳定标识，不依赖容易变化的显示序号；禁止自依赖、循环依赖及指向不存在的子单。

原文事实、评论补充、人工决定和技术建议分别标注。模型不得把示例数值、竞品截图、“可以考虑”、延期能力补成确定的本期要求。技术建议只有经过审核确认后才进入可提交内容。

验收条件必须来自已明确规则或被批准的补充，既包含主路径也覆盖已有的状态边界；不能以“功能正常”代替可验证结果。

模型先做内容清点，再按功能聚合，最后做覆盖与冲突审查。长文按章节分块并跨块归并，不截断尾部冒充全文读取。结构错误、无法追溯的规则、来源遗漏和超过预算都不能直接进入可提交状态。

## 6. 样例拆分与疑问

《勋章挑战系统》正文初稿可分为：

| 标识 | 模块 | 范围 |
| --- | --- | --- |
| M01 | 系统开放与大厅入口 | 开放表、入口和入口倒计时 |
| M02 | 活动周期与结束处理 | 开启/CD、记录窗口、结束状态；结算细节需确认 |
| M03 | 主界面与任务详情 | 奖励区、滚动任务区、详情、未选中提示、状态按钮 |
| M04 | 进度追踪与跨轮次保留 | 开启期间记录、保留历史进度、不清零不下降 |
| M05 | 子活动倒计时与前往跳转 | 总/分倒计时、无倒计时任务、两单位显示和跳转 |
| M06 | 运营沙盘阶段任务接入 | 活动标识、阶段目标、共同逻辑配置化 |
| M07 | 排名类任务接入 | 冲刺、世界BOSS、周排行、竞技场；判定时点需确认 |
| M08 | 收集及累计类任务接入 | 卡牌、活跃、店铺、分钟金币；统计口径需确认 |
| M09 | 单任务奖励与红点 | 达成、领取、已领取、任务与入口红点 |
| M10 | 大奖进度与领取 | 任务数累计、目标门槛、预览和领奖 |
| M11 | 特效接入与演出 | 流光、可领取、解锁及全勋章演出 |

不是固定 11 单，也不是立即新增 11 单。应读取已有单正文做内容比较；不得仅按标题不相同就认定为新增需求。不能自动覆盖已有开发需求、UI需求等宽粒度单。

业务疑问作为运行时待确认数据：排名是实时还是结算；结束后奖励如何处理；15/13 是示例还是配置；名次改善如何映射为不下降的进度；重复卡与分钟金币统计口径；任务底色说明与图示差异。

配置、埋点章节仍未补齐；头像框兼容边界尚需确认；助推礼包是设想。排序和每日宝箱属于已有 TAPD 补充内容，必须区分出处，不伪装成正文提取结果。

## 7. TAPD 模板与字段

总单标题采用系统/功能名称，正文包含原文链接、来源版本、目标、本期范围、排除与待确认事项。功能子单必须形成 TAPD 原生父子关系；读取样例已确认 parent_id 字段存在，实际写入参数和方式仍须核实官方创建契约。

子单正文顺序：功能规则、验收条件、依赖、需求来源、适用的待确认/范围说明。具体规则在前，避免空泛摘要。HTML 内容先转义，结构化生成段落和列表，不直接透传模型 HTML。

父子需求类型、模板、可用初始状态、必填字段由目标项目的真实能力决定。负责人逐单可覆盖，迭代批量可设且父单独立；不从示例单继承完成状态、负责人和优先级。不沿用缺陷字段 current_owner、os 等映射。

自动写入前必须核实需求创建 API、parent_id、workitem_type_id、模板/迭代和人员字段。只读候选不足时由有权限人员提供准确映射；未经核实不可发起猜测性创建。

首版不把飞书附件复制上传到 TAPD。需求正文提供可访问的原始文档/素材引用和确认后的规则；不提供虚构图片地址、内部下载路径或带凭据的临时地址。

## 8. 架构与状态

沿用消息轮询/事件入口，在路由后进入独立需求流程，避免套用代码排查提示词、300 字回复限制和现有短期报告保留策略。

主要边界：

1. 文档读取适配器：认证、内容与素材读取、来源快照；只读外部资源。
2. 拆分器：结构化模型调用、归并、证据与覆盖校验；无 TAPD 写权限。
3. 需求审核协调器：请求、草稿、版本、身份、分页和修改。
4. TAPD 需求适配器：只读核对、已确认的创建契约、纯函数模板生成。
5. 提交协调器与持久化台账：父子映射、批次、单飞、恢复与不确定结果。

复用现有配置、凭据文件解析、进程执行和卡片传输能力，不对无关模块做泛化重构。保持 ESM、可注入副作用和现有依赖约束；额外依赖不得静默安装。

需求流程与故障排查共享单个重操作执行槽；忙时明确告知，不把新请求静默丢弃或直接抢占。审核草稿不长期占用执行槽。事件接收和审核反馈不等待文档/模型/建单完成；同请求的内容修改和提交串行，提交中不可修改该批次。

请求状态：读取中 → 分析中 → 待审核 → 提交中 → 已完成/部分完成/待核对；取消只适用于尚未写入的工作。读取/分析失败可由人发起重试；不会自动变成建单重试。

独立持久化记录保存 requestId、发起人/审核人、来源快照、项目、草稿版本、子单稳定标识与内容、问题/覆盖、父单映射、提交批次、结果。提交账本不随最近 20 条分析报告清理，首版不自动删除。

状态保存和单飞控制集中于协调器。独立请求台账不得由旧的内存快照覆盖；写入意图必须先可靠落盘，再调用外部创建。

## 9. 防重、版本及部分失败

业务身份以目标 workspace 和规范化文档 ID 为基础。同文档重发回到已有草稿/映射，文档版本变化生成待审核差异，不自动创建第二个父单。

已有父单优先通过持久化映射或用户提供的单号绑定，并核对项目和文档。首次迁移时按接口支持的条件分页检索可能关联的父单；多个候选或无法完整检索时由审核人选择/提供，不声称未查到就是不存在。子单比较需要读取正文，标题相似度仅为提示，不能证明等价。

审核人确认时冻结版本、来源、目标和本批次内容。确认后文档重检成功、字段校验通过且台账意图落盘，才开始写入。

创建顺序：父单成功并持久化映射后，按依赖拓扑顺序逐个创建子单。每个结果立即落盘；回填卡片失败不影响已创建状态，不触发重建。

每项创建记录包含稳定提交标识及 payload 指纹。可在描述末尾放置非敏感的短追踪标识以供核对，但不把它当成 TAPD 服务端幂等键。

失败分类：

- 确认未发出请求：可明确重试。
- 接口明确拒绝且确认未创建：修正后由审核人重试失败项。
- 超时、断线、响应异常或发出后未记录结果：状态未知，停止该批次，先查 TAPD。
- 远端发现唯一精确匹配的追踪标识并核对项目/父子关系：补记单号，不重发。
- 查不到、多个匹配、读取不完整或服务端结果仍可能延迟：保持待核对，要求人工核实，不能把查不到当作可自动重试证明。

重启后遗留的提交中项按未知处理。已成功的父子单永不重建。已完成项不自动删除回滚；未开始的剩余项可在核实后继续。后续改稿保留既有映射，修改已创建内容只显示差异，不在首版自动写回。

不宣称具备 TAPD 端到端 exactly-once 保证；依赖本地防重、停止不确定重试和人工核对控制重复风险。

## 10. 安全与认证

TAPD 与模型凭据只从已批准的本地凭据文件读取，不进入参数、错误、日志、卡片、需求正文或 Git。文档读取使用明确的服务身份和授权范围；交互终端用户能读不等于常驻服务一定能读，需独立验证。

文档、评论、附件和模型输出都是非可信数据，不能改变工具权限、请求目标、负责人白名单或提交意图。链接仅允许受控来源，逐次验证重定向，拒绝内网/回环等地址；优先使用平台原生资源读取能力。

完整需求内容只发给项目已批准的模型服务及本次确认的 TAPD workspace，不新增外部渲染/存储服务。运营日志只记请求标识、阶段、耗时、计数和脱敏错误；完整内容留在受控本地草稿，不额外输出原始事件令牌。

权限不足应指明缺失的读取/创建能力并停止相应步骤；不自动申请扩大权限或切换为其他身份。

## 11. 验证与交付门禁

离线自动化验证：

- 显式命令、普通转发、富文本、多个链接与现有故障触发的路由互斥。
- 文档内容分块完整性、重复来源合并、表格读取、资源缺失、评论冲突和版本变化。
- 规则来源、覆盖表、示例数值、延期项、不确定信息和技术建议的校验。
- 草稿修改、依赖检查、身份拒绝、旧卡片拒绝及分页不丢内容。
- TAPD 模板转义、必填字段、父子类型与迭代独立、父单绑定校验。
- 双击提交、并行回调、同文档重发、进程重启、部分创建、超时未知、卡片回填失败。
- 原有代码排查与缺陷提交回归，长任务不阻塞事件接收。

只读集成验证：完整读取真实策划文档及资源清单，核对样例父子结构、服务身份读取权限和目标项目元数据。当前实际文档默认关联既有父单，不新建。

获授权后的写入自测：在用户指定的测试目标创建最小父子样例，读取核对真实关系、字段和富文本格式；再验证卡片修改/确认及部分失败恢复。平台卡片须在真实自测客户端验证，不能用 JSON 单测代替操作验收。写入权限或客户端不可用时如实报告未验证，不宣称完成。

交付顺序：用户审阅书面规格 → 编写并审阅实施计划 → TDD 实现及独立审查 → 离线回归 → 只读集成 → 另行批准的自测写入。生产上线另行确认。
